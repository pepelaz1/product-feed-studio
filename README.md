# Feed Studio

Локальный веб-конвертер товарного каталога на Node.js и SQLite. Принимает CSV, XLSX и JSON с произвольными названиями колонок, находит начало таблицы, предлагает сопоставление полей и проверяет данные. Можно скачать полную очищенную таблицу CSV/XLSX/JSON, краткую таблицу поставщика CSV/XLSX или создать базовый YML-фид для Яндекс Маркета. В интерфейсе видны ошибки по строкам, отдельный CSV-отчёт и история последних выгрузок.

## Запуск

Нужен Node.js 22.9 или новее. Установите зависимости один раз:

```powershell
npm ci
npm start
```

Откройте http://127.0.0.1:4174 и нажмите «Загрузить пример». Кнопка использует `sample/ready-catalog.csv`: пять демонстрационных товаров без ошибок. Рядом есть ссылки на образцы CSV, XLSX и JSON. В Excel-образце выберите лист «Товары»; первые две строки на нём служат примером вводной части прайса. `sample/supplier-catalog.csv` и `.json` показывают каталог без категории и ссылок, с краткими характеристиками. `sample/catalog.csv` содержит две ошибочные строки для проверки диагностики. Для проверки логики: `npm test`.

## Что проверяется

- Обязательные колонки для обычной товарной таблицы: артикул, название и цена. Для YML дополнительно нужны категория и URL товара.
- Краткие характеристики можно сопоставить с колонкой `details`, `характеристики`, `свойства` и похожими заголовками. Они попадают в полную таблицу и в краткую товарную таблицу из четырёх колонок: артикул, наименование, цена, краткие характеристики.
- Строка заголовков ищется автоматически среди первых 30 строк. Если заголовки стоят в первой строке, ничего не пропускается. При необходимости номер строки можно изменить вручную.
- Цена положительная, максимум два знака после запятой; ссылки начинаются с HTTP(S).
- Повторы артикула и некорректные строки попадают в отчёт и исключаются из экспорта.
- Поддерживаются CSV с запятой, точкой с запятой и табуляцией, кавычки и переносы строк внутри ячеек, UTF-8 и Windows-1251. Для XLSX можно выбрать лист; формулы читаются по сохранённому в файле результату. JSON-файл должен содержать массив плоских объектов либо объект с массивом `products`; вложенные объекты отклоняются с понятной ошибкой.
- Очистка выгружается в CSV, XLSX и JSON. Дополнительно доступна краткая товарная таблица CSV/XLSX и отчёт об ошибках CSV. В Excel цена остаётся числом, первая строка закреплена, а значения, похожие на формулы, сохраняются как текст. Старые записи истории, созданные до обновления, не имеют краткой таблицы и JSON-экспорта.
- YML-выгрузка содержит цены в рублях, время в RFC 3339 с часовым поясом UTC, артикулы в `<offer id>`, категории, названия и необязательные описания, фотографии и остатки `<count>`.
- Несколько URL изображений можно перечислить через `;` в одной ячейке. Остаток, если выбран, должен быть целым неотрицательным числом.

Лимиты демо: CSV или XLSX до 2 МБ, до 10 000 строк и 100 колонок Excel. Исходный файл не сохраняется. SQLite-база с историей и сформированными файлами создаётся в `data/` и не попадает в Git.

## Границы примера

Это демонстрация базового цикла обработки каталога по [документации YML Маркета](https://yandex.ru/support/marketplace/ru/assortment/auto/yml), а не готовая интеграция с маркетплейсом или CMS. Выбран сценарий обновления каталога, не отдельный сценарий управления размещением DBS; поэтому атрибут `available` и элемент `<currencyId>` для DBS не выводятся. Для реального магазина нужно согласовать схему исходных данных, дополнительные обязательные характеристики конкретной категории, проверить созданный файл в кабинете продавца, настроить авторизацию и расписание обновлений. CSV-режим не создаёт YML и не требует данных магазина. Ссылки `example.com` в демонстрационном CSV вымышлены, и этот файл нельзя загрузить как действующий каталог. Демо запускается локально; публичный сервер без авторизации для загрузки чужих файлов не предусмотрен.

Краткую товарную таблицу добавили по типу задачи Kwork [о переносе 40 товаров из каталога поставщика в Excel](https://kwork.ru/projects/3268282/view): артикулы, названия, цены, краткие характеристики. [Закрытый проект TecDoc .bdf → CSV](https://kwork.ru/projects/3267867/view) показывает спрос на бинарные и многогигабайтные источники, но этот формат в Feed Studio не поддерживается: ему нужен отдельный адаптер Transbase и потоковая обработка. В старых проектах переноса между CMS встречается [явное сопоставление полей товара](https://kwork.ru/projects/3120181/view); здесь оно выполняется только для CSV/XLSX/JSON, прямой импорт в CMS не реализован. Файлов заказчиков для этих задач в приложении нет; демонстрационные данные созданы отдельно.

## Импорт XML и работа с поставщиками

Внизу страницы доступны два дополнительных блока.

- **YML → CSV/XLSX:** загрузите файл с каталогом YML. Выгружаются ID предложения, название, путь категории, цена, валюта, признак наличия, остаток, первые два фото, остальные фото, описание и URL. Если фото нет, в первых двух колонках будет `NOPIC`. Образец: [example.yml](sample/example.yml).
- **CommerceML → CSV/XLSX:** выберите каталог XML и при необходимости отдельный файл предложений. Экспортируются уровни групп, свойства, НДС, остатки, все найденные типы цен и валюты. Соединение товара и предложения выполняется по полному Ид либо по части до `#`. Образцы: [каталог](sample/example-commerce.xml) и [предложения](sample/example-offers.xml).
- **Объединение прайсов:** выберите 2–5 CSV/XLSX/JSON. Колонки объединяются по названиям, каждая строка получает имя источника из имени файла; ссылка на фото выделяется в отдельную колонку.
- **Сверка поставщиков:** первый файл — ваш каталог, остальные 1–4 файла — прайсы. Используется точный артикул, таблица соответствий или точная пара бренд + модель. При нескольких предложениях выбирается минимальная закупочная цена **с положительным остатком**. Итоговые цена, поставщик и остаток идут в новых колонках. При отсутствии доступного поставщика остаток равен нулю, а исходные колонки не перезаписываются. Примеры: [базовый каталог](sample/example-supplier-a.csv), [поставщик](sample/example-supplier-b.csv), [соответствия артикулов](sample/example-sku-map.csv).

Для сверки задайте наценку, скидку и, если в файле есть USD/EUR, курсы в рублях вручную. Формула: `закупочная цена × курс × (1 + наценка / 100) × (1 − скидка / 100)`. Можно добавить JSON с особыми правилами, например `{"byBrand":{"Демо":{"markup":15}},"bySku":{"LAMP-001":{"discount":5}}}`; приоритет: SKU, бренд, категория, общие настройки. РРЦ выводится справочно и не ограничивает расчёт. Сервис не получает курсы автоматически и не обновляет товары на маркетплейсе.

Новые режимы сохраняют результат и замечания в локальной SQLite и дают ссылки на CSV, XLSX и CSV-отчёт. Исходные файлы после обработки не сохраняются. Лимиты: 2 МБ на файл, максимум 5 прайсов и 10 000 строк результата, 100 колонок. XML с DTD не принимается; реальный CommerceML может требовать адаптера к конкретной выгрузке 1С.
